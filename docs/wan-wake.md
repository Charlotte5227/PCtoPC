# 外部IP／DDNSへのWoL送信

v0.2の「外部から起動」タブは、操作側PCからルーターの外部IPv4／DDNS名へMagic Packetを送信します。ルーターが対象PCのLANへ転送する構成なら、別の常時稼働PCは不要です。PCのWoL対応、BIOSとWindows設定、停止中もNICへ給電されることが前提です。

## アプリに入力する値

| 欄 | 入力内容 |
| --- | --- |
| 起動するPC | 登録済みの接続先 |
| 有線LAN MAC | 起動するPCの有線LANアダプターのMAC。LAN起動と共通 |
| 外部IPv4／DDNS | インターネット側のルーターの外部IPv4、またはそのIPを指すDDNS名 |
| 外部UDPポート | ルーター側で受け付ける番号。初期値3000。1～65535 |

送信先ホストとポートは別欄です。`https://`、パス、`:3000`はホスト欄へ入れません。DDNSレコードにはIPv4（Aレコード）が必要です。複数のIPv4が返された場合は最初のアドレスを使います。アプリは送信のたびにWindowsの名前解決を呼び、Windows／DNSのキャッシュとTTLに従います。

「外部へ起動信号を送る」は設定を保存してから102バイトのMagic Packetを3回送信し、ログへ送信先ホスト・解決したIPv4・UDPポートを表示します。起動が完了するまでの待機や自動接続は行いません。起動後に「接続する」タブへ移動して接続します。

外部WoL用ホストは画面転送用ホストやAgentの接続先と独立しています。例えば、WoLはルーターのDDNS、デスクトップ接続はPCのTailscale IPとして保存できます。Agentの接続ファイルはこの送信方法には不要です。

## BL1500HM → Archer AX23V → PCの例

以下のIPは設定例です。各機器に実際に割り当てられた値へ置き換えてください。

```text
インターネット
  → BL1500HM（グローバルIPv4、外部UDP 3000）
  → AX23V（WAN 192.168.0.2、UDP 3000）
  → PC（LAN 192.168.1.50、UDP 9）
```

1. BL1500HMの「ホームゲートウェイ詳細設定 → LAN側設定 → DHCP固定／除外割当設定」で、AX23Vの**WAN側MAC**と現在のWAN側IPを登録します。DHCP固定割当の設定条件は[公式ガイド](https://kddi-tech.com/hgw-bl1500hm/contents/settings_L4_18.html)を参照してください。
2. BL1500HMの「ネットワーク設定 → ポートマッピング設定」で、LAN側ホストをAX23VのWAN側IP、プロトコルをUDP、ポートを3000に設定して保存します。「any」は使いません。[公式ガイド](https://kddi-tech.com/hgw-bl1500hm/contents/settings_L4_11.html)
3. AX23Vで対象PCのIPアドレス予約とIP・MACバインディングを行い、外部UDP 3000から対象PCの内部UDP 9へポート転送します。[TP-LinkのWoL設定](https://www.tp-link.com/jp/support/faq/923/)
4. PCtoPCの外部送信先には、AX23VのWAN側192.168系アドレスではなく、**BL1500HMの外部IPv4／そのIPを指すDDNS名**を入力します。外部UDPポートは3000、MACは対象PCの値です。
5. 操作側PCをスマートフォンのテザリングなど別回線へ移し、起動信号を送ります。LAN内から外部IP宛ての通信はルーターのNATループバック対応に依存します。

DDNSが二段ルーター内でプライベートIPを登録してしまう構成では動作しません。DDNSのAレコードがインターネット側ルーターの現在のグローバルIPv4を指すことを確認してください。グローバルIPの変更後はDNSキャッシュの更新を待つ必要がある場合があります。

## 確認できること・できないこと

アプリが「送信しました」と表示しても、UDPには起動完了を返す仕組みがありません。PCの起動を確認するには、少し待ってからTailscale／Sunshine／Agentへの接続を試します。シャットダウン直後だけでなく時間を空けても復帰するか確認してください。

WoLパケット自体には認証・暗号化がありません。指定UDPポートへ到達できて対象MACを知る相手は起動信号を送れます。認証付きの経路が必要な場合はTailscale＋Agent中継を利用してください。PCtoPCはファイアウォールやルーターのルールを自動で変更しません。

ローカルUDPのポート指定送受信、ホスト名のIPv4解決、キャンセル、旧設定の互換性を自動テストしています。実際のルーターを経由した外部からの起動は、利用環境で確認が必要です。
